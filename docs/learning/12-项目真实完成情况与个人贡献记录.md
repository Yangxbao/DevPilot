## 5. 面试话术：如何诚实回答"这是不是你写的"

### 5.1 推荐的开场框架（诚实 + 理解深度，30 秒版）

> "这个项目是我定义需求、制定验收标准，并和 AI 协作完成的：代码由 AI 生成，我负责范围裁剪、环境搭建、跑通全部验证——20 个后端集成测试对真实 MySQL、31 个 pytest、18 步 E2E 和 7 张浏览器验收截图，这些我都能当场复跑。更重要的是我能讲清每个设计决策为什么这么做、哪些路径没验证过——比如真实大模型 Provider 我还没接过真实 Key，一直跑的是 mock，这条我不会含糊。"

要点：**先亮协作方式**（不给人"揭穿"的机会）、**再亮验证证据**（可复跑的数字）、**最后主动亮边界**（未验证清单）。

### 5.2 分场景应对

**场景 A：面试官直接问"代码是你写的吗？"**
> "不是全部。生成方式我刚才说明了。我可以证明的是我对系统的掌控：您随便挑一个模块，我把对应的表结构、接口契约、测试用例和失败语义讲给您；您也可以问我哪些部分我还没读懂——比如 Python 侧某几行，我还在按我的学习路线补课（可出示 docs/learning/11 的六周计划）。"
- 姿态：不辩解、不缩小，把话题引到"可验证的理解"上。

**场景 B：面试官问"那你这个项目的价值是什么？"**
> "三个：一是完整走过一遍'从 PRD 到验收'的工程流程，包括用测试和 E2E 建立验证网；二是产出一套我反复核对过的设计文档和一个真实可跑的系统；三是我把'AI 辅助开发'本身当成一个需要管理的工程问题——所以有了这份完成度记录、未验证清单和学习计划。"

**场景 C：面试官追问你没做过的细节（比如"Redis 黑名单你们怎么部署的"）**
> 诚实回答模板："这个路径我们没有在真实 Redis 上验证过，本机跑的是进程内降级实现——`TokenBlacklistConfig` 启动探测失败会 WARN 并切换。代码我读过：Redis 实现是 key 加 TTL 等于 Token 剩余有效期。但'部署过'我不说，没验证过的我会说清楚。"
- 这个模板的关键结构：**承认未验证 + 展示代码级理解 + 不扩大声明**。

**场景 D：面试官质疑"AI 生成的项目没有含金量"**
> "我理解这个偏见。两个可以当场检验的东西：第一，30 道设计取舍题，任何一道您都可以往深里追——降级矩阵、并发防重、注入防护的边界我都答得出来；第二，我给您指出这个项目里我自己发现的三个真实缺陷/文档偏差（见第 3 节），这说明我在读代码而不是在背项目。"

### 5.3 红线（绝对不要说的话）

- 不要说"我一个人写的"、"手写了全部代码"——与第 0 节声明矛盾，一旦被追问具体细节会连环崩塌。
- 不要把 mock 模式的效果说成"接入了真实大模型的效果"。
- 不要宣称 Docker 部署、生产上线、性能压测等未发生的事。
- 不要在简历/README 写任何第 2 节表格里"未验证"的能力为"已完成"。
- 不要在被追问时现编数字（测试数、超时秒数、上限值）——所有数字以第 7 节速查卡为准，记不住就说"我文档里有记录，会后发您"。

### 5.4 统一口径小词典（同一个词，全场合一个说法）

| 词 | 统一口径 |
|---|---|
| "AI 辅助生成" | 代码与文档由 AI 生成，我负责需求定义、验收标准、环境搭建、运行验证与后续学习维护（第 0 节原文） |
| "mock 模式" | `LLM_PROVIDER=mock`，服务端基于真实检索证据做模板化汇总、不联网；回答带【演示模式说明】且 `mode="mock"` |
| "派生数据" | 可随时删除重建的数据：SQLite 索引库、code_file/code_chunk；与业务主数据（MySQL）相对 |
| "已验证" | 我本人运行过并有输出/截图证据（第 1 节） |
| "设计了未实装/未验证" | 文档里有设计但代码没有，或代码有但我没跑过真实环境（第 2、3 节） |
