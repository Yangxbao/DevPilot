# 01 - 开发环境搭建（Windows）

> 目标：在一台 Windows 机器上，从零装好跑 DevPilot 需要的全部工具，并起一个**独立的 MySQL 3307 实例**。
> 为什么强调"独立实例"：不污染你机器上可能已有的 MySQL（比如课程实验装在 3306 的那个），也和 `backend/src/main/resources/application.yml` 的默认连接串 `jdbc:mysql://127.0.0.1:3307/devpilot` 保持一致，改配置为零。

## 1. 为什么需要这些工具

| 工具 | 版本 | 谁需要它 | 为什么 |
|---|---|---|---|
| JDK | 21 | backend | `backend/pom.xml` 声明 `<java.version>21</java.version>`，Spring Boot 3.x 要求 Java 17 起步，项目实际按 21 编译 |
| Maven | 3.9+ | backend | 构建工具。仓库里**没有** mvnw wrapper，所以必须本机安装 |
| MySQL | 8.0+ | backend | 业务主数据。**必须 8.0+**：`code_chunk` 表用了 `FULLTEXT ... WITH PARSER ngram`（中文检索依赖它，5.x 行为不同） |
| Python | 3.11+ | ai-service | `ai-service/requirements.txt`：fastapi 0.115.6 / pydantic 2.10.4，3.11 是实测可用的版本 |
| Node.js | 22 LTS | frontend | Vite 6 + Vue 3.5（`frontend/package.json`），Node 22 是当前 LTS |
| Redis | 可选 | backend | 没有 Redis 后端会自动降级为进程内 Token 黑名单（`TokenBlacklistConfig.java`），本地开发可以不装 |

## 2. JDK 21 安装要点

1. 下载 Temurin JDK 21 的 Windows x64 `.msi`（或 zip）安装。
2. 配置环境变量 `JAVA_HOME` 指向 JDK 根目录（例如 `C:\Program Files\Eclipse Adoptium\jdk-21.x.x`），并把 `%JAVA_HOME%\bin` 加入 `Path`。
3. Maven 需要 `JAVA_HOME`，很多 IDE 也读它，所以不要只改 `Path`。

验证：

```bat
java -version      # 应输出 21.x
echo %JAVA_HOME%
```

## 3. Maven 安装要点

1. 下载 apache-maven-3.9.x 的 binary zip，解压到无空格路径（如 `C:\tools\apache-maven-3.9.9`）。
2. 把解压目录下的 `bin` 加入 `Path`。
3. 国内网络建议在 `%USERPROFILE%\.m2\settings.xml` 配一个阿里云镜像，否则第一次 `mvn` 拉依赖会很慢。

```bat
mvn -v    # 应同时显示 Maven 3.9.x 和 Java 21
```

## 4. Python 3.11 安装要点

1. python.org 下载 3.11.x Windows installer，安装时勾选 **Add python.exe to PATH**。
2. 验证 `python --version`。如果装了多个版本，用 `py -3.11` 区分。
3. ai-service 的依赖单独建虚拟环境，避免污染全局（在 `ai-service/` 目录下执行）：

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 5. Node 22 安装要点

- 官网下载 Node 22 LTS 的 `.msi` 一路下一步即可；验证 `node -v` 与 `npm -v`。
- frontend 只在跑界面时需要。只用后端 + AI 服务 + 脚本的话可以不装。

## 6. 用本机 MySQL 二进制起一个 3307 独立实例

这是本篇的重点。有两种办法：

- 办法 A（Docker）：`docker-compose.yml` 里的 mysql 服务监听 3306，需要改端口映射；本机 Docker 路径**未经验证**（见 00 篇声明）。
- 办法 B（本机二进制，**已验证**）：下载 MySQL 8 的 Windows zip 包，手动初始化一个数据目录，监听 3307。下面只讲办法 B。

| | 办法 A（Docker） | 办法 B（本机二进制） |
|---|---|---|
| 前置 | 装 Docker Desktop | 下载 MySQL zip 包（约几百 MB） |
| 隔离性 | 容器内自带，删容器即干净 | 独立数据目录，删目录即干净 |
| 与本项目配置的匹配 | `docker-compose.yml` 默认 3306 + 专用账号 | `application.yml` 默认 `127.0.0.1:3307` + root 空密码，零配置 |
| 本项目验证状态 | 未验证 | 已验证（后端 `mvn test` 与 E2E 都跑在 3307 上） |

为什么端口选 3307 而不是 3306？因为很多同学机器上已经有一个占 3306 的 MySQL（课程实验、XAMPP 之类）。DevPilot 的配置默认就指向 3307，独立实例互不干扰，也避免动到旧库的数据。

### 6.1 下载与解压

到 dev.mysql.com 下载 **MySQL Community Server 8.0.x - Windows (x86, 64-bit), ZIP Archive**（选不带 debug 的那个，约几百 MB）。解压到例如 `C:\tools\mysql-8.0\`，里面应有 `bin\mysqld.exe`、`bin\mysql.exe` 等。

### 6.2 初始化数据目录

选一个数据目录（示例用 `C:\mysql-3307\data`，你可换成别的，路径含中文或空格容易踩坑）：

```bat
:: 1) 先建数据目录
mkdir C:\mysql-3307\data

:: 2) 初始化（--initialize-insecure = root 密码为空）
C:\tools\mysql-8.0\bin\mysqld.exe --initialize-insecure --datadir=C:\mysql-3307\data
```

**为什么用 `--initialize-insecure`**：它把 root 密码置空。DevPilot 的默认配置（`application.yml`）就是 `username: root`、`password: 空`，两边对上即开即用。`--initialize`（不带 -insecure）会生成随机密码打印在日志里，还得手动改密码，没必要。这只适用于本地演示库，生产库绝不能这样。

初始化成功时，数据目录里会出现 `mysql/`、`sys/`、`ibdata1` 等文件，控制台输出 `Root password is empty` 之类的提示。

### 6.3 启动实例（前台方式，适合学习阶段）

```bat
C:\tools\mysql-8.0\bin\mysqld.exe --port=3307 --datadir=C:\mysql-3307\data --console
```

- `--port=3307`：监听 3307 而不是默认 3306。
- `--console`：日志打到当前窗口，方便看报错。
- 窗口保持开着，实例就活着；关窗口即停。想后台跑可以用 `--install` 注册 Windows 服务（`mysqld --install MySQL3307 --defaults-file=...`），学习阶段建议先用前台方式。
- 如果 3306 已有一个 MySQL 在跑，这个实例互不影响（端口不同、数据目录不同）。

### 6.4 建库

另开一个窗口：

```bat
C:\tools\mysql-8.0\bin\mysql.exe -h 127.0.0.1 -P 3307 -u root --skip-password
```

进去后执行（**两个库都要建**，`devpilot` 给开发用，`devpilot_test` 给 `mvn test` 用）：

```sql
CREATE DATABASE devpilot      DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE devpilot_test DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
SHOW DATABASES;   -- 确认两个库都在
```

说明：

- 只建空库即可，**不要手工建表**。表结构由 Flyway 在后端启动时从 `backend/src/main/resources/db/migration/V1__init.sql` 自动创建（见 04 篇）。
- 字符集用 `utf8mb4` 与 V1 脚本中每张表的声明一致，避免中文乱码。
- 如果你想给这个实例设个密码，设完之后需要同步改 `application.yml` 的 `DB_PASSWORD` 环境变量或默认值，`backend/src/test/resources/application-test.yml` 里同理（它支持 `TEST_DB_USERNAME` / `TEST_DB_PASSWORD` 环境变量）。

### 6.5 常见坑（Windows 特有）

1. **路径含中文或空格**：`--datadir=D:\我的 文件\mysql\data` 这类路径会让 `mysqld --initialize` 报莫名其妙的错。用纯英文无空格路径。
2. **忘了 `--initialize-insecure` 直接启动**：数据目录为空时直接 `mysqld --port=3307` 会拒绝启动（提示需要初始化）。顺序必须是：先 initialize，再启动。
3. **重复初始化**：对同一个已有数据的目录再跑 `--initialize-insecure` 会报错（`... data directory has files in it`）。想重来就先清空数据目录。
4. **3306/3307 混淆**：本机已有 3306 实例时，客户端工具默认连 3306，会连错库。所有连接都显式写 `-P 3307`。
5. **防火墙**：本机回环（127.0.0.1）连接不经过防火墙拦截，一般不用管；只有想从局域网其他机器连才需要开端口，而 DevPilot 本地开发不需要。
6. **杀毒软件拦截 mysqld 写文件**：个别场景下初始化极慢或失败，把数据目录加入白名单即可。

## 7. 可选：Redis

`application.yml` 默认连 `127.0.0.1:6379`。不装也行：启动时 `TokenBlacklistConfig` 探测 Redis 失败会打一行 WARN 并切换到进程内黑名单实现。区别是：进程内黑名单只对单个后端进程有效，且重启后端后黑名单清空（已登出的 Token 如果还没过期，理论上又能用——本地演示无感）。想完整体验就装一个 Redis for Windows 或用 Docker 起一个。

## 8. 环境变量总览（本机开发基本不需要改）

`backend/src/main/resources/application.yml` 的本地默认值已经是一套能跑的配置：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SERVER_PORT` | 8080 | 后端端口 |
| `DB_URL` | `jdbc:mysql://127.0.0.1:3307/devpilot?...` | 就是上面 6.3 起的实例 |
| `DB_USERNAME` / `DB_PASSWORD` | root / 空 | 与 `--initialize-insecure` 对齐 |
| `REDIS_HOST` / `REDIS_PORT` | 127.0.0.1 / 6379 | 可不装（降级） |
| `JWT_SECRET` | dev-only 开头的默认串 | 本地够用，生产必须换 ≥32 字节强随机 |
| `JWT_EXPIRE_MINUTES` | 120 | 登录态有效期（分钟） |
| `AI_SERVICE_BASE_URL` | `http://127.0.0.1:8200` | ai-service 地址 |
| `INTERNAL_TOKEN` | `dev-internal-token` | 与 ai-service 的 `config.py` 默认值一致 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | admin / admin123456 | 首次启动引导创建 |
| `STORAGE_PATH` | `./data/storage` | 上传 zip 的暂存目录（相对 backend 运行目录） |
| `CORS_ORIGINS` | `http://localhost:5173,...` | 前端开发端口 |

仓库根目录的 `.env.example` 有全部变量的注释版；其中 Compose 用的值（如 `DB_URL=jdbc:mysql://mysql:3306/...`）是给 Docker 部署用的，**不要**照抄到本机直跑的场景。

## 9. 验证清单（逐条勾，全过再进 02 篇）

| # | 命令 | 预期输出 | 不符时排查 |
|---|---|---|---|
| 1 | `java -version` | `openjdk version "21.x"` | `JAVA_HOME` 未配好或 PATH 里还有别的 JDK 抢先 |
| 2 | `mvn -v` | `Apache Maven 3.9.x` 且 `Java version: 21` | Maven 用的 Java 不是 21（Maven 跟随 `JAVA_HOME`） |
| 3 | `python --version` | `Python 3.11.x` | 装了多版本时用 `py -3.11` 或重装勾选 Add to PATH |
| 4 | `node -v` | `v22.x`（跑前端才需要） | 官网重装 LTS 包 |
| 5 | `C:\tools\mysql-8.0\bin\mysql.exe -h 127.0.0.1 -P 3307 -u root --skip-password -e "SELECT VERSION();"` | `8.0.x` | mysqld 窗口没开着 / 端口写错 |
| 6 | 同上连接里 `SHOW DATABASES;` | 能看到 `devpilot` 和 `devpilot_test` | 回到 6.4 建库 |
| 7 | 同上连接里 `SHOW VARIABLES LIKE 'character_set_server';` | `utf8mb4`（最好如此；不是也不致命，Flyway 建表时按表声明覆盖） | 初始化时未指定字符集，重建数据目录即可 |

第 5、6 步也可以用图形工具（Navicat / DBeaver / IDEA Database 面板）完成：主机 `127.0.0.1`、端口 `3307`、用户 `root`、密码留空。

两条心得：

1. **环境变量改完必须重开终端**（以及重开 IDEA），否则读到的还是旧值——这是 Windows 下最常见的"我明明配了"。
2. 所有命令行里的路径（`C:\tools\mysql-8.0`、`C:\mysql-3307\data`）都是示例，换成你自己的目录时，初始化和启动两处必须一致。

常见坑：

1. `mysqld` 启动即退、控制台报 `InnoDB: ... errno 13`：数据目录路径写错或权限不足，检查 `--datadir` 是否与初始化时完全一致。
2. 3307 被占用：`netstat -ano | findstr 3307` 找占用进程。
3. `mvn` 报 `JAVA_HOME is set to an invalid directory`：`JAVA_HOME` 必须指向 JDK 根目录（`bin` 的上一级），不是 `bin` 本身。

## 10. 附录：用 docker-compose 只起 MySQL 的参考（未验证）

如果机器上已有 Docker，也可以只借用 compose 文件里的 MySQL，其余服务照旧本机直跑。参考改法（**本机未实际执行过，仅方向性参考**）：

```yaml
# 在 docker-compose.yml 的 mysql 服务里，把端口映射
ports:
  - "3306:3306"
# 改成（只改宿主机一侧，容器内仍是 3306）
ports:
  - "3307:3306"
```

然后 `docker compose up -d mysql`，用 `127.0.0.1:3307` 连接（账号 `devpilot/devpilot123`，来自 compose 的 `MYSQL_USER/MYSQL_PASSWORD`）。三点注意：

1. compose 默认创建的是 `devpilot` 账号，而 `application.yml` 默认用户是 root——要么给后端设 `DB_USERNAME/DB_PASSWORD` 环境变量，要么进容器补账号。
2. compose 的 MySQL 容器自动建 `devpilot` 库，**不会建 `devpilot_test`**，测试库仍需手工 `CREATE DATABASE`。
3. 这条路径没有在本机验证过，遇到问题优先回退到第 6 节的二进制方案（已验证）。

## 11. 收尾建议

把本篇用到的三个路径记在一个地方（笔记或环境变量备注）：

- MySQL 8 zip 解压目录（含 `bin/mysqld.exe`）；
- 3307 实例的数据目录（含 `data/`）；
- 启动 MySQL 的那行命令（`mysqld --port=3307 --datadir=... --console`）。

以后每次开机先起 MySQL 再起后端，形成固定顺序后，"搭环境"这件事就不会消耗你的耐心。下一篇让三个服务真正跑起来。
