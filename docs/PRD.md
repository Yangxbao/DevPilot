# DevPilot 产品需求文档（PRD）

> 版本：v1.0（2026-10-25）　状态：MVP 范围已冻结
> 本文档是开发范围的唯一依据：凡不在 P0 清单中的能力，README 不得宣称已完成。

## 1. 背景与要解决的问题

中小软件研发团队普遍面临四个真实痛点：

1. **代码知识只存在于老成员头脑里**。新成员理解"这个功能在哪实现的"只能逐个问人，老人被打断，知识无法沉淀。
2. **Bug 定位依赖经验**。拿到一段异常堆栈，新人不知道该去代码库的哪个位置排查；错误信息与代码之间没有自动关联。
3. **缺陷管理与代码上下文割裂**。禅道/Jira 里的缺陷单只有文字描述，没有代码证据；AI 分析的结果也没有地方沉淀和流转。
4. **重型方案用不起**。Sourcegraph、Copilot Enterprise 等产品面向大企业，价格高、部署复杂；小团队需要一个能自己部署、数据不出内网的轻量方案。

## 2. 产品定位

**DevPilot 是一个自托管的 AI 研发协作平台**：把代码库导入 → 索引 → 检索 → 带证据的 AI 问答与 Bug 根因分析 → 缺陷任务闭环，串成一条完整工作流，并配套多用户权限与项目数据隔离。

一句话：**让"检索代码、分析 Bug、跟踪缺陷"在同一个平台里完成，且每条 AI 结论都附带可核对的代码证据。**

## 3. 目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 新成员 小李 | 我想搜"文件上传的校验逻辑在哪"，系统能按文件路径+行号给出代码片段，而不是让我翻整个工程 |
| 开发 小王 | 我把一段 NullPointerException 堆栈贴进 Bug 分析，系统告诉我最可疑的代码位置和理由，并附上证据 |
| 开发 小王 | 分析完的点子可以直接转成缺陷任务，指派给同事，状态流转有记录 |
| 项目负责人 老张 | 我打开仪表盘就能看到：几个项目、索引任务成败、缺陷分布、AI 分析次数——全部是真实数据 |
| 管理员 老陈 | 我能创建/禁用用户；普通用户看不到我项目里的任何数据 |

## 4. 竞品简析与差异化

| 产品 | 强项 | 不足（对小团队而言） |
|---|---|---|
| Sourcegraph | 企业级代码搜索 | 商业授权昂贵，无 AI 缺陷闭环 |
| GitHub Copilot / Cursor | IDE 内辅助 | 个人向，无团队级缺陷管理、无自托管知识库 |
| Sentry | 错误聚合 | 不做代码库级根因分析，无检索 |
| 各类开源 RAG 问答 | 文档问答 | 大多只索引文档不做代码，且缺少缺陷流转闭环 |

**DevPilot 的差异化**：代码+文档混合检索、每条结论必须带证据、分析与缺陷任务打通、自托管、可降级运行（无外网/无 Key 也能演示）。

## 5. 功能范围

### P0（MVP，必须验收通过）

| # | 能力 | 验收标准 |
|---|---|---|
| 1 | 用户认证与权限 | 注册/登录/登出；ADMIN 与 USER 角色；服务端逐接口鉴权；用户 B 无法读取用户 A 的项目数据（自动化越权测试证明） |
| 2 | 项目与仓库管理 | 创建项目；上传 zip 或导入公开 Git URL；超大文件/二进制/依赖目录/敏感文件过滤有明确规则和记录；导入状态与失败原因可查 |
| 3 | 索引与检索 | 代码分块入库；关键词搜索返回文件路径+行号+片段；条件允许时提供语义/混合检索；支持重新索引；不支持的语言有明确提示 |
| 4 | AI 代码库问答 | 基于真实检索结果回答，答案含证据引用（可点击核对）；证据不足时明确说不确定；真实模型与 Mock 模式在界面上明确区分；AI 服务不可用时报错清晰 |
| 5 | Bug 辅助分析 | 输入错误信息/堆栈/复现步骤，输出：摘要、可能原因、证据、影响范围、验证建议、修复方向、置信度；只读不改代码；分析记录可回看 |
| 6 | 缺陷任务管理 | 创建/流转/指派/筛选/分页；AI 分析可关联缺陷；状态流转由服务端校验，非法流转被拒绝 |
| 7 | 基础仪表盘 | 全部数字来自真实数据库查询；空数据有空状态提示 |

### P1（路线图，MVP 未实现，见 README"已知限制"）

Git 提交记录分析、变更影响面分析、测试建议生成、团队文档库、异步 AI 任务队列、分析导出、操作审计日志、任务失败自动重试、生产级监控告警。

### Non-Goals（明确不做）

- ❌ 自动修改用户代码 / 自动提交 PR（MVP 只读）
- ❌ IDE 插件、浏览器插件
- ❌ 多租户 SaaS、计费
- ❌ 私有 Git 凭据托管（MVP 仅支持公开 HTTPS 仓库与 zip 上传）
- ❌ 生产级安全合规认证（SOC2 等）
- ❌ 超大规模（>10 万文件）仓库性能优化

## 6. 非功能需求（MVP 基线）

- **安全**：密码 BCrypt 存储；JWT 认证；导入内容视为不可信数据（不执行、防路径穿越、防压缩包炸弹）；密钥全部走环境变量；提示注入防护。
- **性能**：单仓库 ≤ 2000 文件索引 < 2 分钟；关键词搜索 P95 < 1s（本演示规模）；AI 问答总超时 90s。
- **可靠性**：导入/索引失败不产生脏数据（事务+状态机）；重复触发索引被幂等拒绝；AI 调用有超时、重试与降级。
- **可维护**：统一响应/异常/校验；数据库迁移脚本化；核心流程有自动化测试。
